## What was verified, and how

Everything below was actually executed, not reasoned about.

- **Lint / format / types.** `ruff check` clean, `ruff format --check` clean
  across 48 files, `mypy --strict` clean across 39 source files.
- **Tests.** `36 passed, 10 skipped` — the 10 skips are the integration tests,
  each naming the unreachable dependency.
- **Migration DDL.** `alembic upgrade head --sql` renders the complete schema
  without a database. Reviewed line by line: `CREATE EXTENSION IF NOT EXISTS
  vector`, correct constraint names matching the metadata convention
  (`pk_users`, `uq_users_email`, `fk_user_roles_user_id_users`), `BIGINT
  GENERATED BY DEFAULT AS IDENTITY`, `JSONB DEFAULT '{}'::jsonb`, all five
  indexes, and a linear revision chain `0001 → 0002`.
- **The API actually boots.** Started under uvicorn with no dependencies
  running. Result: `HTTP 503`, `"status": "degraded"`, both probes reporting
  `probe exceeded 1s timeout` at ~989 ms — proving the timeout bound is real and
  the process serves traffic while its dependencies are down.
- **Correlated structured logging, end to end.** Live server output, including
  uvicorn's own records, rendered as JSON with `execution_id`, `request_id`,
  `service`, `version`, `environment` on every line. The startup line logs
  `postgresql+asyncpg://custops:***@localhost:5432/custops` — masked.
- **Request correlation.** Inbound `X-Request-ID: smoke-check-1` was honoured,
  echoed in the response header, and appeared in the response body.

## What is NOT verified

Do not claim these work; they are unproven (Rule 20).

1. **`docker compose up`** — never run. Image tags (`pgvector/pgvector:0.8.6-pg17`,
   `redis:8.10`, `ghcr.io/astral-sh/uv:0.11.23`) were checked against their
   registries, but the composition, the build, the entrypoint and the healthchecks
   are all untested.
2. **Migrations against a real server.** Offline DDL generation does not exercise
   privileges — in particular, whether the connecting role may `CREATE EXTENSION`.
3. **`/health` returning 200.** No dependency has ever answered. The 200 path is
   covered only by stub probes.
4. **pgvector actually installed.** The extension has never been created.
5. **`entrypoint.sh` line endings.** `.gitattributes` forces LF, but this has not
   survived a real checkout-and-build cycle.

### Closing the gap

With Docker: `docker compose up --build`, then `curl localhost:8000/health`.
Without: install PostgreSQL + pgvector and Redis per the README, then
`uv run alembic upgrade head` and `uv run pytest` — all 46 tests should pass.

## Known issues and open questions

- **ADR-003 (Redis role) is deliberately unresolved.** BUILD_SPEC D2 assigns
  Redis the checkpoint store; §7 assigns that to PostgreSQL. Both cannot hold.
  Redis currently stores nothing. Decide by Phase 5, including the option of
  removing it.
- **Migrations run as a superuser.** `CREATE EXTENSION` requires it. Splitting
  the migration role from a least-privilege application role is Phase 13.
- **uvicorn's access log is disabled**, replaced by a correlated
  `http_request_completed` line from the middleware. uvicorn logs from the
  protocol layer, outside the request context, so its lines always carried
  `"request_id": null` — an access log that cannot be correlated defeats §16.
- **`audit_events` has no writer.** The table and its contract exist; Phase 12
  owns the write path. It is foundation, not a stub.
- **No CI.** Phase 14.
- **Nothing is committed.** The working tree is staged but no commit was made.
